# kh-diagram-svg: 틀로 본문 그림 그리기

본문 그림은 SVG 틀 하나로 그린다. 틀이 색·선·글꼴·프레임을 정하므로 그림에는 **좌표와 글만** 적는다. 새 모양을 고안하지 말고 예시 그림과 같은 모양으로 맞춘다. Python·Node 같은 프로그램은 쓰지도 설치하지도 않는다. 필요한 것은 파일을 쓰는 일과 브라우저로 여는 일뿐이다.

이 문서에서 `<스킬>`은 이 SKILL.md가 있는 폴더다. 작업 전에 읽는다.

- `<스킬>/references/style.md`: 그림 규칙(프레임, 색, 글자, 선, 화면 그림, 파일 이름, 원고에 넣기). **전체를 읽는다.**
- `<스킬>/references/svg-template.md`: 클래스 표, 부품 조각, 좌표 요령, 확인 방법. **전체를 읽는다.**
- `<스킬>/assets/svg-template/frame-S.svg`: 복사해 쓰는 틀.
- `<스킬>/references/svg-template-examples/`: 틀로 그린 예시 3장(단계 흐름 `skill-basics-4-01`, 칸 나열 `work-procedure-2-01`, 구조 `github-basics-2-01`).

## 1. 무엇을 그릴지 정한다

- **한 그림에 한 가지.** 그림이 말하려는 것을 한 문장으로 적는다. 그 문장이 그림 제목이 된다(예: "회의록은 메모가 세 단계를 거쳐 공유 폴더에 올라가는 흐름입니다"). 둘을 말하고 싶으면 그림을 나눈다.
- 그림 파일을 둘 폴더(문서가 그림을 읽는 폴더, 보통 `images/`), 표제란에 적을 과정·문서 이름, 그림 번호를 정한다. 모르면 사용자에게 묻는다.
- 화면을 본뜨는 그림이면 실제 화면 문구·버튼 위치를 사용자 자료에서 확인한다. 모르면 그리지 않고 묻는다.
- 사람·인물 그림으로 비유하는 만화는 이 스킬로 그리지 않는다. 같은 내용을 상자와 화살표로 그린다.

## 2. 비슷한 예시를 고른다

| 종류 | 본뜰 예시 |
|---|---|
| 단계 흐름(번호 붙은 상자 가로 줄) | `skill-basics-4-01.svg` |
| 칸 나열(가운데 흐름 + 위아래 칸, 칸 안 여러 줄) | `work-procedure-2-01.svg` |
| 구조(영역 안 상자, 영역 사이 화살표) | `github-basics-2-01.svg` |
| 화면 설명(창 + 빨간 번호 + 범례) | 예시 없음. `svg-template.md`의 번호 원·범례·화면 부품 조각을 조합한다 |

예시를 열어 상자 폭·간격·글자 위치를 그대로 가져오면 여백과 글자 크기가 저절로 맞는다.

## 3. 틀을 복사해 그린다

`svg-template.md`의 "순서"를 따른다. 요약하면:

1. `<스킬>/assets/svg-template/frame-S.svg`를 그림 폴더에 `2-01.svg`처럼 복사한다.
2. 제목(`aria-label`과 `class="title"` 글), 표제란(과정 이름, `그림 2-1`), 높이(`[H]` 네 곳)를 고친다.
3. 맨 아래 "그림 내용" 자리에 부품 조각을 적는다.

```svg
<rect class="area" x="40" y="196" width="230" height="140" rx="4"/>
<text class="h" x="56" y="263">받는 것</text>
<text class="sub" x="56" y="283">회의 메모, 지난주 회의록</text>
<path class="arr-i" d="M272,266 L318,266"/>
<text class="point" x="40" y="484">맨 아래에는 회색으로 요점을 한 줄 적습니다.</text>
```

`<style>`·`<defs>`·테두리·표제란·저작권 줄은 고치지 않는다. 그림 내용에 색(hex), `style=`, `font-size=`, `opacity`를 적지 않고 클래스만 쓴다. 클래스로 안 되는 모양이 필요하면 멈추고 사용자에게 묻는다.

## 4. 브라우저로 확인한다

글자 폭은 아무도 계산해 주지 않는다. 반드시 그려진 모양을 본다. SVG를 브라우저(Edge, Chrome 등)로 열고 `svg-template.md`의 "확인" 다섯 가지를 하나씩 본다. 직접 볼 수 없으면 `svg-template.md` "좌표 요령"대로 여유를 더 두고, 사용자에게 브라우저로 열어 다섯 가지를 봐 달라고 부탁한 뒤 알려 준 문제를 고친다. 넘치거나 겹치면 좌표를 옮기거나 문장을 줄이거나 두 줄로 나눈다. 글자 크기를 규칙 밖으로 줄이지 않는다.

## 5. 원고에 넣는다

- `![대체 텍스트](images/2-01.svg)`를 **단독 문단**으로 둔다. 절 제목 바로 아래, 번호 단계 앞에 놓는다. 캡션은 달지 않는다.
- 대체 텍스트는 그림에서 봐야 할 것을 한 문장으로 쓴다. 구조·흐름 그림은 "…을 보여 주는 그림"으로 끝내고, 화면 그림은 `화면 이름: 보이는 요소 나열`로 쓴다.

그림을 고칠 때는 같은 SVG 파일을 열어 좌표와 글을 고친다.

## 지켜야 할 값

| 항목 | 규칙 |
|---|---|
| 색 | 클래스만: 기본 남색, 초록은 원격·완료·결과·권장, 빨강은 주의·삭제·번호 표시, 회색은 보조 설명. 옅은 면은 영역 구분에만 |
| 글자 | 제목 23(틀에 있음), 상자 제목 15~17(`h`=16), 라벨 13~14, 보조 12~12.5(`sub`), 요점 줄 13.5(`point`). 굵기는 보통과 `b`만 |
| 줄바꿈 | 자동 줄바꿈이 없다. 긴 문장은 `<text>` 두 개로 나누고 줄 간격 19~24. 연속 공백은 한 칸으로 보인다 |
| 모서리 | 요소의 `rx`: 상자·영역 4, 창 8, 단계 칸 10, 버튼 5 |
| 금지 | 그라디언트, 그림자, 투명도, 이모지, 새 색 |
| 파일 이름 | `장-순번`(`2-01.svg`), 표제란 `그림 2-1`. 장이 없는 글은 `<글 주소>-1.svg`, 표제란 `그림 1` |
| 사이트 색 | 그림 색은 그림 전용이다. 문서·사이트의 디자인 색을 그림에 쓰지 않는다 |

## 자주 하는 실수

| 실수 | 확인·예방 |
|---|---|
| 글자가 상자·테두리를 넘음 | 한글 한 글자는 글자 크기의 약 0.86배, 영문 소문자·숫자는 약 0.5배 폭이다. 상자는 가장 긴 줄보다 32 이상 넓게. 브라우저로 본다 |
| 화살표가 글자를 지남 | 가로 화살표 이름은 선보다 10 위나 22~24 아래, 세로 화살표 이름은 옆에 |
| 아래 글이 표제란·저작권 줄을 덮음 | 요점 줄 마지막 줄을 `H-60~H-54`에. 모자라면 높이를 늘린다(680까지) |
| 높이를 한 곳만 고침 | 첫 줄 svg의 viewBox 넷째 값·height, `[H]` 표시 rect 두 개, `translate(0,H)`를 같이 고친다. 아래쪽이 잘리거나 빈칸이 생기면 이것이다 |
| 모르는 내용을 지어냄 | 받은 내용에 없는 담당·날짜·설명은 `(확인 필요)`로 남긴다. 맨 아래 요점 줄도 받은 내용을 다시 말하는 데서 그친다 |
| 그림이 안 보임 | `<style>`·`<defs>`를 지웠거나 태그를 닫지 않았다. 틀에서 다시 복사해 내용만 옮긴다 |
| 색을 hex로 직접 씀 | 그림 내용에서 `#`를 찾아 클래스로 바꾼다 |
| 번호 원과 범례 번호가 다름 | 브라우저에서 하나씩 맞춰 본다 |
| 표제란 번호와 파일 이름이 다름 | `그림 2-1`과 `2-01.svg`, 원고의 `images/2-01.svg`를 같이 고친다 |
