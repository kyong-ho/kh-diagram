# kh-diagram: 본문 그림 그리기 (figlib)

본문 그림은 모두 `figlib.py` 하나로 그린다. 이 모듈이 색·프레임·부품을 고정하므로 그림 스크립트에는 **구도와 글만** 적는다. 새로 고안하지 말고 예시 그림과 같은 모양으로 맞춘다. SVG를 손으로 쓰거나 만들어진 SVG를 직접 고치지 않는다.

이 문서에서 `<스킬>`은 이 SKILL.md가 있는 폴더다. 작업 전에 읽는다.

- `<스킬>/references/style.md`: 규칙의 원본(프레임, 색, 글자, 선, 화면 그림, 파일 이름, 원고에 넣기). **전체를 읽는다.** 이 문서와 어긋나면 style.md를 따른다.
- `<스킬>/scripts/figlib.py`: 쓸 수 있는 상수와 부품. 짧으니 전체를 읽는다.
- `<스킬>/references/examples/`: 실제로 쓰인 그림 스크립트 5개 과정. 결과 SVG는 `<스킬>/references/reference-svg/`에 있다.

## 0. 프로젝트 준비 (처음 한 번)

그림 스크립트는 사용자 프로젝트 안에 둔다. 프로젝트에 `scripts/figures/figlib.py`가 없으면 아래를 복사한다. 이미 있으면 덮어쓰지 말고 그것을 쓴다(그 프로젝트가 고친 부품이 있을 수 있다).

```bash
mkdir -p scripts/figures
cp <스킬>/scripts/figlib.py <스킬>/scripts/build.py <스킬>/scripts/check.mjs scripts/figures/
```

새 과정(또는 글 묶음)마다 틀을 복사하고 `course.py`의 과정 이름(표제란에 들어감)과 출력 폴더(문서가 그림을 읽는 폴더)를 고친다.

```bash
cp -R <스킬>/assets/course-template scripts/figures/<과정>
```

틀의 `ch01.py`는 예시 그림이다. 첫 그림을 쓸 때 내용을 바꾸거나 지운다.

| 그림 | 스크립트 | 결과 | 표제란 |
|---|---|---|---|
| 장이 있는 교육 자료 | `scripts/figures/<과정>/chNN.py`(여러 장이면 `ch06_07.py`) | 출력 폴더의 `6-02.svg` | `<과정 이름>` · `그림 6-2` |
| 장이 없는 글(리서치 등) | `scripts/figures/<묶음>/<글 주소>.py` | 출력 폴더의 `<글 주소>-1.svg` | `<묶음 이름>` · `그림 1` |

그림 스크립트는 첫 줄 주석(`# AI 스킬 가이드 4장 그림.`) 뒤에 `from course import *`만 쓰고, 그림마다 `# 그림 4-1: 무엇을 보여 주는지` 주석으로 시작한다.

## 1. 무엇을 그릴지 정한다

- **한 그림에 한 가지.** 그림이 말하려는 것을 한 문장으로 적는다. 그 문장이 그림 제목이 된다(예: "저장소는 내 PC와 GitHub, 두 곳에 있습니다"). 둘을 말하고 싶으면 그림을 나눈다.
- 프레임을 고른다.

  | 프레임 | 쓰는 곳 | 만드는 법 |
  |---|---|---|
  | `P` 개념 만화형 | 비유로 흐름을 훑는 개념 장(보통 1장) | `s=P(번호, "제목", "한 줄 설명")`. 960×480 고정 |
  | `S` 도면형 | 그 밖의 모든 그림(화면 설명, 구조, 흐름, 판단 순서) | `s=S(960, 높이, "제목", "그림 6-2")`. 높이는 내용에 맞춰 420~680 |

- 화면을 본뜨는 그림이면 실제 화면 문구·버튼 위치를 사용자 자료나 공식 문서에서 확인한다. 모르면 그리지 않고 묻는다. 화면 문구는 실제 표기 그대로 적는다.

## 2. 비슷한 예시 그림을 본뜬다

같은 종류의 그림을 하나 골라 `<스킬>/references/examples/`의 스크립트를 열고 좌표 간격을 그대로 가져온다. 예시 값에서 시작하면 여백·글자 크기가 저절로 맞는다. 결과 모양은 `reference-svg/`의 같은 이름 파일로 본다.

| 종류 | 본뜰 그림 |
|---|---|
| 구조(두 영역과 그 사이 화살표) | `github-basics/ch02.py`의 2-01, `research/ai-memory-gbrain.py`의 그림 1, 틀의 `ch01.py` |
| 단계 흐름(번호 붙은 상자 가로 줄) | `skill-basics/ch04.py`의 4-1 |
| 칸 나열(가운데 흐름 + 위아래 칸, 칸 안 여러 줄) | `work-procedure/ch01_04.py`의 2-01. 칸 번호는 제목 앞 `①`, 여러 줄 칸은 `s.r` + `s.t` 반복 |
| 화면 설명(창 + 빨간 번호 + 범례) | `github-basics/ch06_07.py`의 6-02 |
| 판단 순서 | `github-basics/ch06_07.py`의 7-01 |
| 비유 만화(`P`) | `github-basics/ch01.py` |

예시 폴더의 `course.py`는 스킬 안에서 돌도록 경로가 맞춰져 있으므로 프로젝트에 복사하지 않는다. 과정 전용 부품(`github-basics/course.py`의 `git`, `desktop`)이 필요하면 함수만 옮겨 온다.

## 3. 스크립트를 쓴다

```python
# 그림 2-1: 저장소는 두 곳에 있다
s=S(960,560,"저장소는 내 PC와 GitHub, 두 곳에 있습니다","그림 2-1")
s.box(242,170,160,62,"파일들","README.md 등")          # 제목 16 굵게 + 보조 12.5 회색
s.p("M606,190 L712,190","g"); s.t(659,180,"푸시",13.5,GRN,700,"middle")
s.t(40,500,"같은 저장소가 두 곳에 있고, 푸시와 풀로 서로 맞춥니다.",13.5,MUTE)  # 맨 아래 요점
s.save("2-01")
```

부품을 먼저 쓰고, 없을 때만 `s.r`·`s.t`·`s.p`를 조합한다.

| 할 일 | 부품 |
|---|---|
| 제목·설명이 있는 상자 | `s.box(x,y,w,h,제목,보조)` |
| 영역(옅은 면 + 이름) | `s.r(x,y,w,h,TINT,INK)` + `s.t(x+18,y+26,이름,15,INK,700)` |
| 화살표 | `s.p("M.. L..", c)` — `c`는 `i` 남색, `g` 초록, `r` 빨강, `m` 회색. 돌아오는 결과는 `dash="5 4"` |
| 번호 원 | `s.b(x,y,n)`(남색), 화면 위 누를 곳은 `callout(n,x,y)`(빨강, 흰 테) |
| 번호 설명 | 오른쪽 세로 `legend([...])`, 아래 가로 `legend_row([...],y)` |
| 화면 틀 | `appwin`, `browser`, `field`, `button`, `check`, `radio`, `dropdown`, `diffline` |
| 단계 칸 | `panel(x,y,w,h,n,제목)` |
| 만화 인물·사물(`P`) | `person`, `robot`, `doc`, `pc`, `cloud`, `stamp`, `bubble`, `lock` |
| 화면 그림 아래 안내 | `note(y)` — "실제 화면을 단순하게 그린 그림입니다…" |

여러 그림에 반복되는 화면(그 프로그램의 창 틀 등)은 그 과정의 `course.py`에 부품으로 만든다. 다른 과정에서도 쓸 부품이면 프로젝트의 `figlib.py`에 둔다.

## 4. 만든다

```bash
python3 scripts/figures/build.py <과정>
```

Python 3 기본 설치만 있으면 된다. 내용이 바뀐 그림만 다시 쓰고 `쓴 그림: …` 을 출력한다. 출력이 없으면 바뀐 그림이 없다. 출력 폴더를 건드리지 않고 시험하려면 `FIG_OUT=<임시 폴더>`를 앞에 붙인다.

## 5. 눈으로 확인한다

글자 폭은 스크립트가 계산하지 않는다. 반드시 그려진 모양을 본다.

```bash
node scripts/figures/check.mjs <출력 폴더>/6-02.svg
```

이 명령이 브라우저로 그림을 그려 PNG(기본 위치는 임시 폴더 `kh-diagram-check/`, `--out`으로 바꿈)를 남기고, 테두리 밖 글자·글자끼리 겹침·상자 경계에 걸친 글자·글자를 지나는 선을 후보로 알린다. 폴더를 주면 그 안의 그림을 모두 본다. PNG 이름 앞에는 폴더 이름이 붙는다(`images-6-02.png`).

- 처음이면 프로젝트에 `npm install -D @playwright/test`와 `npx playwright install chromium`이 필요하다. 설치를 사용자가 원하지 않거나 Node가 없으면, SVG를 브라우저로 열어 같은 네 가지를 눈으로 본다.
- 후보가 없어도 PNG를 열어 본다. 번호 원과 범례 번호가 맞는지, 그림이 한 가지를 말하는지는 검사가 보지 못한다.
- 후보는 실제 문제가 아닐 수도 있다(일부러 겹친 취소 표시, 같은 자리에 덮어쓴 글자). PNG로 확인하고, 실제 넘침·겹침만 고친다.
- 고칠 때는 좌표를 옮기거나 문장을 줄이거나 두 줄로 나눈다. 글자 크기를 규칙 밖으로 줄이지 않는다.

## 6. 원고에 넣는다

- `![대체 텍스트](images/6-02.svg)`를 **단독 문단**으로 둔다. 절 제목 바로 아래, 번호 단계 앞에 놓는다. 캡션은 달지 않는다.
- 대체 텍스트는 그림에서 봐야 할 것을 한 문장으로 쓴다.
  - 구조·흐름 그림: "…을 보여 주는 그림"으로 끝낸다.
  - 화면 그림: `화면 이름: 보이는 요소 나열`.
- 실습이 있는 장에는 개념 그림 하나와 실습 화면 그림을 합쳐 2~5개를 둔다.

## 7. 마친다

그림이 들어간 문서를 실제 화면(넓은 화면과 휴대폰 폭)에서 열어 그림 주소가 맞고 글자가 읽히는지 본 뒤 완료라고 말한다. PNG는 올리지 않고 SVG만 쓴다.

## 지켜야 할 값

모두 `references/style.md`와 `figlib.py`에 있는 값이다.

| 항목 | 규칙 |
|---|---|
| 색 | `figlib.py` 상수만: 기본 `INK` 남색, `GRN` 원격·완료·권장, `RED` 주의·삭제·번호 표시, `MUTE` 보조 설명, 글자 `G`, 구분선 `LINE`. 옅은 면 `TINT`·`GRNT`·`REDT`·`AMBT`는 영역 구분에만(예시 그림에서 받는 것·입력 칸은 `TINT`, 결과는 `GRNT`, 주의할 점·정리본 보기 칸은 `AMBT`). `AMB`는 만화 캐릭터(`git`)의 면에만 쓰였다. 화면 그림의 기본 버튼은 `BLUE`. hex를 새로 적지 않는다. 새 색이 필요해 보이면 멈추고 사용자에게 제안한다 |
| 글자 | 제목 23(프레임이 넣음), 상자 제목 15~17, 라벨 13~14, 보조 설명 12~12.5. 예시 그림의 맨 아래 요점 줄은 13.5 `MUTE`. 굵기는 400과 700만 |
| 줄바꿈 | 자동 줄바꿈이 없다. 긴 문장은 직접 두 줄로 나누고 줄 간격은 예시처럼 19~24. 연속 공백은 한 칸으로 보인다 |
| 선 | 테두리 1.5, 화살표 2(만화형 3.5). 모서리는 상자 4, 창 8, 말풍선 16 |
| 금지 | 그라디언트, 그림자, 투명도. 이모지 |
| 화면 그림 | 캡처하지 않고 단순하게 다시 그린다. 누를 곳에 `callout`, 같은 번호 설명을 `legend`·`legend_row`로 |
| 파일 이름 | `장-순번`(`6-02`), 운영체제별은 `4-01-win`·`4-01-mac`. 표제란은 `그림 6-2`. 장이 없는 글은 `<글 주소>-1`, 표제란 `그림 1` |
| 사이트 색 | 그림 색은 그림 전용이다. 문서·사이트의 디자인 색을 그림에 쓰지 않고, 그림 색을 사이트에 쓰지 않는다 |
| 글꼴 | `figlib.py`의 `FONT`(맑은 고딕, Apple SD Gothic Neo, Noto Sans KR 순). 바꾸지 않는다 |

## 자주 하는 실수와 확인 방법

| 실수 | 왜 생기나 | 확인·예방 |
|---|---|---|
| 글자가 상자·테두리를 넘음 | 글자 폭을 재지 않고 좌표만 정함 | `check.mjs`. Mac 글꼴 실측으로 한글은 한 글자에 글자 크기의 약 0.86배, 영문 소문자·숫자는 약 0.5배를 차지한다(16 굵게 한글 10자 ≈ 138). 다른 운영체제 글꼴은 폭이 다를 수 있으니 여유를 둔다 |
| 화살표·구분선이 글자를 지남 | 화살표 이름을 선 위에 바로 얹음 | 가로 화살표의 이름은 선보다 10 위(`y-10`)나 22~24 아래에, 세로 화살표는 옆에 둔다(`research/ai-memory-gbrain.py` 그림 1, `github-basics/ch02.py` 2-01). `check.mjs`의 "선이 글자를 지남" |
| 아래 글이 표제란·저작권 줄을 덮음 | 높이를 정하지 않고 글을 계속 내림 | 표제란은 오른쪽 아래 `W-278`부터 `H-38`~`H-8`, 저작권은 왼쪽 `H-17`에 있다. 맨 아래 요점 줄의 마지막 줄은 예시처럼 `H-60`~`H-54`에 둔다. 모자라면 `S`의 높이를 늘린다(680까지) |
| 범례 번호와 화면 번호가 다름 | 번호를 손으로 매김 | PNG에서 `callout` 번호와 `legend` 순서를 하나씩 맞춰 본다 |
| 색을 hex로 직접 씀 | 비슷한 색을 새로 고름 | 스크립트에서 `"#`를 찾아 `#fff` 말고는 상수로 바꾼다 |
| 투명도·그라디언트가 들어감 | `opacity`·`fill-opacity`를 붙여 흐리게 함 | 결과 SVG에서 `opacity`·`Gradient`·`filter`를 찾는다. 흐린 효과 대신 `MUTE`나 옅은 면 상수를 쓴다 |
| 한 그림에 여러 메시지 | 장의 내용을 그림 하나에 다 담음 | 제목 문장이 한 가지를 말하는지 본다. 아니면 나눈다 |
| SVG를 직접 고침 | 작은 수정이라 파일을 바로 엶 | 다음 `build.py` 실행 때 덮어써진다. 스크립트를 고친다 |
| 표제란 번호와 파일 이름이 다름 | 그림을 옮기며 한쪽만 고침 | `S(..., "그림 6-2")`와 `save("6-02")`를 같이 고친다. 원고의 `images/6-02.svg`도 |

## 모양이 그대로인지 확인할 때

프로젝트의 `figlib.py`를 고쳤거나 예시와 모양이 다르게 나오는 것 같으면 아래로 확인한다. 예시 76장을 다시 만들어 기준 그림과 비교한다. 결과는 임시 폴더에만 쓴다.

```bash
python3 <스킬>/scripts/verify_examples.py scripts/figures/figlib.py
```

`기준 그림 76장 모두 같음.`이 나오면 같은 모양이다. 저작권 문구(`COPYRIGHT`)나 색을 바꾼 프로젝트에서는 모두 다르다고 나오며, 그 차이가 의도한 것인지 사용자에게 확인한다.
